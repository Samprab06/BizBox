# Live Jev interior policies

`POST /api/projects/:projectId/interior-policies` accepts `{comparisonId,baseline,variant}`. Both drafts must be scoped to the same owned saved comparison/site/city and be runnable coffee scenarios. Geometry labeled Matterport-bound must also match the canonical approved stored source binding and corrected coordinate marker. Assumed geometry remains explicitly unverified. No customer metrics are authored by Jev.

For three synthetic personas per side, the server asks three Noul questions (queues 0/4/10) using observed route length, seating, price, service time, staff, effective capacity and estimated wait. Responses directly populate the engine's stay-by-queue probabilities. Actual returned model versions must agree across both policies; mixed versions fail explicitly. Requested alias is restricted to verified `jev-latest`; arbitrary `JEV_MODEL` settings are rejected. `INTERIOR_JEV_CACHE_EPOCH` is an explicit server-side coherence epoch: rotate it for an intentionally paid coherent retry after an alias-version mismatch. No automatic refetch/retry occurs.

Official sources checked November 15, 2026: [System One API](https://docs.typesafe.ai/api/system-one.md) documents named questions, structured state, returned model and usage; [pricing](https://help.typesafe.ai/articles/5187202169-how-much-does-jev-cost) states $0.042 per million input tokens, output free, with no separate per-request, failed-request or minimum fee. Preparation caps each JSON payload at 4,096 UTF-8 bytes, three questions, no assets/long-context headers, and reserves four copies of the serialized bytes at a conservative $1/M input-token ceiling. This is an approved conservative reservation envelope, not a provider-published tokenizer formula. Six calls maximum per uncached pair; retries and rate-limit retries are disabled. Responses are cached by full semantic wire request, project, requested alias, policy version and epoch.

## One aggregate original grant

The original authorized cap is 1,000,000 microUSD ($1), including the historical reservation of 26,864 microUSD from the initial six-call experiment. A grant is never initialized by a route, never reset per request/project/process and never refunded after a failure. Atomic SQL reservation updates enforce the aggregate cap before every outbound attempt. A project-scoped pending claim/120-second lease prevents duplicate cross-worker requests; same-process identical pairs share one pending promise. Browser cancellation propagates before each reservation/call and into the provider fetch. Completed responses remain cached, and prior reservations remain counted.

Runtime uses dedicated `interior_jev_grants`, `interior_jev_reservations`, `interior_jev_policy_cache` and `interior_jev_policy_claims` tables. Drizzle migration `0011_interior_jev_policies` creates them without creating/activating a grant. Missing persistence, key, ownership, canonical source or active grant fails explicitly; no assumed policy is relabeled Jev. The standalone `scripts/interior-policy-schema.sql` mirrors this migration for review; do not independently apply both paths. `scripts/interior-policy-grant-init.sql` requires the latest sealed reservation and handoff receipt, inserts once and has no reset/upsert path.

## Provider authenticity

Preparation returns `{policies:{baseline,variant},usage:{requests,reservedMicrousd,cacheHits},receipt:{version:1,digest,signature}}`. The receipt HMAC uses a domain-separated server `INTERIOR_JEV_API_KEY`, binding canonical project, comparison, both full drafts and both policy snapshots. No signing secret reaches the client. A client-supplied `source: jev` field alone is not provider evidence.

`POST /api/projects/:projectId/interior-policies/verify` accepts `{comparisonId,baseline,variant,policies,receipt}` and returns `{valid:true}` only after signature and current owned source checks. Verification performs no provider calls, reservations or database writes. Changing the draft, comparison, project or probabilities invalidates the receipt. Key rotation invalidates existing receipts. Assumed geometry is not made measured by a Jev signature.

Seed the DB grant from that exact sealed total only after target write approval. Never give both CLI and DB separate $1 allowances. No schema, hosted import, grant activation or provider request was executed merely by creating these files.
