## Owner flow

1. Finish the business brief, including plain typed areas to favor or avoid.
2. The saved brief is converted through the existing intake adapter and sent to `POST /api/sites`. Arrive at the bird’s-eye map without an implicit property selection or card carousel. Click an address tag/numbered pin to focus that exact property and open its source facts in the Property panel. Multiple returned spaces at the same coordinates appear there by rent and size. An optional Show list offers the same selection by keyboard. Saving changed criteria refetches listings; conversation-only edits do not. Selection uses the actual site ID in URL/details/voice context; closing clears it. Mesh-level building picking remains HAC-77.
3. Existing comparison/interior features remain secondary actions rather than the exploration landing screen. In the optional list select two or more locations and explicitly choose **More → Compare locations**. The existing comparison controller calculates the result. Results distinguish modeled customers/contribution from observed data, report demand provenance and disappear when their selected-location set becomes stale. There is no separate baseline screen or required replay.
4. Open **Interior** for a selected listing. The existing interior registry must return a matching, non-demo scan before a Matterport viewer appears. Parent-building scans are labeled separately from exact-space scans. A floor plan or unavailable state appears otherwise.
5. After a saved comparison includes this site, expand **Indoor experiment · Test service capacity**. The existing station experiment controller compares the current setup with additional stations/staff, preserving its original seeds, service calls and budget confirmation. This is an operations comparison; it does not claim to edit a Matterport model or simulate arbitrary renovations.
6. The Property/List/Chat panel shares the allocated desktop side column. Chat stays mounted while another panel is shown, preserving its draft/history. The narrow desktop Codex preview reflows panels below a properly sized map and collapses chat initially, rather than covering the map. Text and Voice use the same existing conversation and draft. Voice uses the existing `VoicePanel` and reactive orb, with the selected site supplied in voice context.

## Real options from onboarding

`useSiteSearch` retains its existing loading/example/live interface and adds typed search readiness to the comparison controller. Missing/invalid/unsupported onboarding displays **Complete your brief → Finish brief**, HTTP/network/schema failures display **Listings unavailable → Retry**, and a successful empty result displays **No matching spaces → Revise criteria**. Only an actual search response establishes that no locations matched. Filter counts, the server's empty reason and unsupported typed-note limitations stay under Details.

The existing intake observer handles same-tab saves and cross-tab storage updates. A profile-only fingerprint avoids refetching when only chat history changes, immediately hides old criteria results, and aborts obsolete requests. Saved comparison results are invalidated when criteria change. A selected space remains selected while eligible; when changed filters remove it, details close and its stale URL selection is cleared. Another property is never silently selected. Candidate cards retain actual listing IDs, source rent/size and at most two fact-grounded reasons such as **Within rent limit** or a requested, listed building feature; no new score or inferred business suitability is introduced.

The underlying search applies city, active-for-lease status in the supplied kit, retail use, explicit size bounds, known base-rent ceiling and supported ground-floor/corner-or-endcap/frontage/parking requirements. Unknown rents remain labeled unknown. Typed area/customer notes are preserved but do not become geographic or audience filters; staffing, price tier and operating economics belong to later comparisons. This does not verify current broker availability, zoning, licensed use or demand.

SITE_SEARCH_DEV_ORIGIN=https://hackprincetonweb.vercel.app
